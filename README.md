# 100-Days-of-Python---Custom-Learning-Plan
A custom-developed learning plan of 100 Python projects designed to take one from the lower end of intermediate to the lower end of advanced, with a solid grasp of the language and confidence building functional tools from it. Before getting into it, I feel the need to state that while this is called 100-days-of-Python, the objective is consistency and daily learning. I work full time in IT and System Engineering and am a full time student, so some days my time for this endeavor is quite limited. With that said, while a project may not be turned out daily, they will be turned out as often as possible and there is daily learning behind the scenes. Even if I'm not able to ship the final version yet, on a day where I have not committed, I am still working behind the scenes in what little free time I have to learn the necessary elements for the next project, plan it, and turn out a first draft that can be quickly refactored and shipped next day.
While AI was used in the development of the total list of what each day-to-day artifact will be, and the requirements for what a successful artifact looks like; AI was not used at any point to write or assist with writing these programs. Resources used to fill knowledge gaps and debug tough issues: stackoverflow, python 3.14.4 documentation, and individual module/library documentations. You can see the total list of all the projects in this repo. 

Another Note- I fully recognize that this is not a standard ReadMe as far as both content and format are concerned, however, this is not meant to be an explanation of the individual code in each file. This ReadMe is meant to be for me to reflect on my journey as a developer and what I've learned on a day to day basis.

*STARTING ON DAY 5*
I've realized that I retain information better when I write an explanation of what I do/did as though I were explaining it to a friend with a general knowledge of up/down. Beginning with day 5, I will be writing explanations for each day, not really how the code works, but what I learned writing it and what skills I refined. The intention is to communicate my learning journey clearly with documentation of my progress as a developer and general enthusiast, whilst providing an artifact for me to go back through at a later date and reflect on.

--*DAY 1*-- Wrote Log Parser that returns total number of logs by type

--*DAY 2*-- Edited Log Parser to include searching by severity, date, and keyword

--*DAY 3*-- Wrote a program that takes a directory path supplied by the user and iterates through it using a recursive function to search for all files, and return the total file size in KB being utilized by each type of file. Learned the Pathlib module for this.

--*DAY 4*-- Wrote a program that recursively searches through a specified directory, given by a user, and hashes only the files contained in the entire directory tree using hashlib, and returns a list of the duplicate files. Program uses Hashlib and a chunk size of 4KB to hash each file progressively without needing to load entire large files into memory.

--*Day 5*-- Wrote a program that takes a text file given by the user and parses through it to determine statistics about the file such as word count, sentence count, unique words used, breadth of vocabulary, and the most used words. Useful for text analysis and authorship attribution. Through this, I learned a bit more about comprehensions, file manipulation, and data processing. A challenge that I faced initially was getting the function that returns the average word length to actually read the unique_words dictionary. At first, it was reading letters. That one took about 20 minutes to solve but the solution was fairly simple. I learned about Lambda functions and what they do in order to complete this micro-project. Lastly, I refined my architecture development skills by taking the project requirements given by ChatGPT and breaking them out into what data I'll need to track, what data type it should be, how I should track it optimally, and what needs to be done to it. I created a flowchart and full pseudocode for this project, developed an initial working artifact, and then refined twice before shipping. As with all projects in this REPO, this was done without the use of AI. Skills refined: Reading files with context managers, File-path validation with pathlib, String manipulation and character filtering, List and generator expressions, Dictionaries and frequency counting, Dictionary .items(), Tuple indexing, Sorting dictionary data by value, Lambda functions as sorting keys, Basic statistical calculations, Input validation, Functions, Python's __name__ == "__main__" entry-point pattern. Another thing I tried to implement today is descriptive names for my variables and functions to make it easier to read the code. I noticed that in previous days, I've gotten lazy and named them simple and non-descriptive things for the sake of easier typing, but that caused problems in debugging and interpretation yesterday. That's something I addressed, successfully, today with more descriptive names even if they're longer or more complicated.

--*Day 6*-- Refactored the program in Day 5 to export some settings into a config.json file that controls some of the variables and desired behavior of the program. To do this, I had to learn what a JSON file is and how to use it in Python. This wasn't a new concept nor was it that hard to implement, it was just new to me. I picked it up in about 30 minutes though and finished the whole of Day 6 in about 45. A light refactor and the application of the concept made it stick pretty well and I can confidently say I've got the grasp of it now. The next trick was looking a little bit at what could be managed that way. The low hanging fruit was the variables for word_count, etc. but what I had to search a little bit deeper for was using the JSON file to allow the user to pick how many 'top words' they want to display in the output of the document analysis and whether or not they want it to be case sensitive. These are now clearly labelled in the JSON document and the whole thing works as intended. Additionally, just as a side note, I've added graceful handling of either invalid or non-sensible JSON values in the config file.In this repo, I've uploaded the 'config.json' document for visibility and I've replaced the original Day 5 project with the day 6 refactor.

--*Day 7*-- Day 7 didn't consist of writing a new program, but rather learning how to use the argparse module to turn one of the utilities already written into a command line utility that runs interactively. The required me to remove all hardcodings, upgrade the original utilities error handling, and rewrite some user input grabs to instead pull directly from the command. I added 1 required argument and 3 optional arguments that can be used to change programmatic behavior and/or update JSON configuration files from the command line instead of simply running the python file. It now handles like a fully functional command line program. The point of today was to loosely refine my programming skills in Python directly while learning more about full programmatic development; crossing that line where a program that operates in a sandbox can be run like an application. 

--*Day 8*-- Day 8 required me to relearn a skill I'd lost since college which was parsing csv files. I started by watching tutorials on how to use the csv module and I had GPT generate me a spare csv file for a mock ticketing system for an IT helpdesk company. After getting the csv file, I started by making a minimum viable product. I was able to declare the correct variables off the rip and create a product with proper logic that displayed the desired output by topic. From there, I needed to refactor because I had intentionally hardcoded some things with the intention of keeping flow and returning later. The first step in the refactor was formatting output how I wanted it and making it look pretty. The next step in the refactor was getting rid of all hardcodings and ensuring that the dictionaries were built dynamically. This ensures that I could feed any semi-similar csv file to my ticketing system's and this parser will work for it. Overall, today wasn't so much about learning new skills as it was about refining current skills. Some skills refined: Use of data types and dictionaries, logic, data flow management, soft-coding, dynamic creation, and program design.
